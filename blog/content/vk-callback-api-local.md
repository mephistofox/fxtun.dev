Callback API ВКонтакте присылает события сообщества POST-запросом с JSON на адрес вашего сервера: новое сообщение, комментарий, вступление в группу. Чтобы принимать их на своём компьютере, запустите обработчик на `localhost:8080`, откройте туннель `fxtunnel http 8080 --domain vk-bot` и впишите адрес `https://vk-bot.fxtun.ru` во вкладке Callback API сообщества. При подтверждении адреса ВКонтакте пришлёт событие `confirmation`, и обработчик должен ответить строкой из настроек. На остальные события нужно отвечать `ok`. Ниже по шагам: рабочий обработчик на Python, проверка секретного ключа, повторы и что делать, когда адрес меняется.

## Как устроен Callback API

По [документации ВКонтакте](https://dev.vk.com/ru/api/callback/getting-started) всё держится на нескольких правилах:

- **Одно событие — один запрос.** Тело — JSON с полями `type` (тип события), `event_id`, `v` (версия API), `object` (сам объект) и `group_id`.
- **Ответ — строка `ok` и HTTP 200.** Если сервер несколько раз подряд ответит ошибкой, Callback API временно перестанет слать на него уведомления.
- **Подтверждение адреса.** После ввода адреса и нажатия «Подтвердить» приходит событие типа `confirmation`. Сервер должен вернуть заданную строку. Строка время от времени меняется: при добавлении нового сервера или правке настроек старого нужно указать новую.
- **Секретный ключ.** Произвольная строка из поля «Секретный ключ» приходит в каждом уведомлении в поле `secret`. По нему обработчик отличает ВКонтакте от чужих запросов.
- **Повторы.** Если сервер не ответил `ok`, событие придёт снова через 10 секунд, 3 минуты, 10 минут, 30 минут и час. В повторных запросах есть заголовок `X-Retry-Counter` с числом неудачных попыток.

Серверов в одном сообществе может быть до 10, у каждого свой набор событий и своя версия API. Это пригодится: рабочий бот продолжит получать события на боевой сервер, а отладочный адрес вы добавите отдельно.

## Шаг 1. Сообщество и ключ доступа

Бот работает от имени сообщества, и вы должны быть его администратором. По [быстрому старту для чат-ботов](https://dev.vk.com/ru/api/bots/getting-started):

1. В сообществе откройте **Управление → Сообщения** и включите сообщения сообщества, иначе боту нельзя будет написать.
2. Там же, в **Настройках для бота**, включите **Возможности ботов**.
3. В **Управление → Дополнительно → Работа с API** нажмите **Создать ключ**, отметьте нужные права и подтвердите. Боту, который отвечает на сообщения, нужен доступ к сообщениям сообщества.

Ключ даёт доступ к API от имени сообщества. В код его не вписывайте, публично не выкладывайте. Если ключ утёк, удалите его в том же списке, и он перестанет действовать.

## Шаг 2. Обработчик

Обработчик на стандартной библиотеке Python, без зависимостей. Он подтверждает адрес, проверяет секретный ключ, пропускает повторы и отвечает на входящее сообщение его же текстом.

```python
# vk_hook.py
import hmac
import json
import os
import random
import urllib.parse
import urllib.request
from http.server import BaseHTTPRequestHandler, HTTPServer

CONFIRMATION = os.environ["VK_CONFIRMATION"]  # строка из вкладки Callback API
SECRET = os.environ["VK_SECRET"]              # поле «Секретный ключ»
TOKEN = os.environ["VK_TOKEN"]                # ключ доступа сообщества
API_VERSION = "5.199"                         # та же версия, что в настройках сервера
seen = set()                                  # event_id уже обработанных событий


def vk_api(method, **params):
    params["v"] = API_VERSION
    req = urllib.request.Request(
        "https://api.vk.ru/method/" + method,
        data=urllib.parse.urlencode(params).encode(),
        headers={"Authorization": "Bearer " + TOKEN},
    )
    with urllib.request.urlopen(req, timeout=10) as resp:
        answer = json.load(resp)
    if "error" in answer:
        raise RuntimeError(answer["error"].get("error_msg"))
    return answer["response"]


class Hook(BaseHTTPRequestHandler):
    def reply(self, text, code=200):
        body = text.encode()
        self.send_response(code)
        self.send_header("Content-Type", "text/plain; charset=utf-8")
        self.send_header("Content-Length", str(len(body)))
        self.end_headers()
        self.wfile.write(body)

    def do_POST(self):
        try:
            event = json.loads(self.rfile.read(int(self.headers.get("Content-Length", 0))))
            kind = event["type"]
        except (ValueError, KeyError, TypeError):
            return self.reply("bad request", 400)

        if kind == "confirmation":
            return self.reply(CONFIRMATION)
        if not hmac.compare_digest(str(event.get("secret", "")).encode(), SECRET.encode()):
            return self.reply("forbidden", 403)
        if event.get("event_id") in seen:
            return self.reply("ok")  # повтор уже обработанного события

        if kind == "message_new":
            msg = event["object"]["message"]
            try:
                vk_api("messages.send", peer_id=msg["peer_id"],
                       message="Получил: " + msg.get("text", ""),
                       random_id=random.randint(1, 2**31 - 1))
            except Exception as err:
                print("send failed:", err, flush=True)
                return self.reply("error", 500)  # ВКонтакте повторит событие
            print("message from", msg["from_id"], ":", msg.get("text", ""), flush=True)

        seen.add(event.get("event_id"))
        self.reply("ok")


HTTPServer(("127.0.0.1", 8080), Hook).serve_forever()
```

Что здесь важно:

- **Подтверждение идёт первым.** На `confirmation` обработчик возвращает строку и больше ничего не проверяет. Остальные события без правильного `secret` получают `403`. Ключ сравнивается функцией `hmac.compare_digest` за постоянное время, чтобы по времени ответа нельзя было подбирать его посимвольно. Сравниваются байты: строки с не-ASCII символами `compare_digest` не принимает.
- **`ok` только после обработки.** Если ответ отправить не удалось, обработчик возвращает `500`, и ВКонтакте повторит событие по расписанию. `event_id` запоминается только после успеха, поэтому повтор не потеряется.
- **Повтор успешного события пропускается.** Если `ok` потерялся по дороге, событие придёт ещё раз. Набор `seen` не даст ответить пользователю дважды. Он живёт в памяти и очищается при перезапуске: для отладки этого хватает, в рабочем боте храните `event_id` в базе.
- **Формат `message_new` зависит от версии API.** С версии 5.103 сообщение лежит в `object.message`, в более старых прямо в `object` ([список событий](https://dev.vk.com/ru/api/community-events/json-schema)). Поэтому версию в коде и в настройках сервера держите одинаковой.
- **`random_id`** — число в пределах int32, по которому ВКонтакте отсекает повторную отправку одного и того же сообщения. `0` отключает проверку ([messages.send](https://dev.vk.com/ru/method/messages.send)).

Запуск (строку подтверждения возьмёте на шаге 4, пока можно поставить любую):

```bash
export VK_CONFIRMATION=d8v2ve07
export VK_SECRET=$(openssl rand -hex 16)
echo "$VK_SECRET"   # это значение впишете в поле «Секретный ключ»
export VK_TOKEN=ключ_доступа_сообщества
python3 vk_hook.py
```

На Windows в PowerShell: `$env:VK_CONFIRMATION="d8v2ve07"; $env:VK_SECRET="…"; $env:VK_TOKEN="…"; python vk_hook.py`.

Проверить обработчик можно до всякого ВКонтакте, вторым окном терминала:

```bash
curl -d '{"type":"confirmation","group_id":1}' http://127.0.0.1:8080/
```

```console

```

## Шаг 3. Туннель

Установите клиент и войдите, это делается один раз:

```bash
curl -fsSL https://fxtun.ru/install.sh | sh
fxtunnel login
```

На Windows первая строка заменяется на `irm https://fxtun.ru/install.ps1 | iex` в PowerShell.

Откройте туннель на порт обработчика. Имя поддомена задайте сразу: адрес будет записан в настройках сообщества, и подтверждать новый после каждого перезапуска неудобно.

```bash
fxtunnel http 8080 --domain vk-bot
```

```console
Connecting to fxtunnel server...
Tunnel established!
HTTP:  http://vk-bot.fxtun.ru
HTTPS: https://vk-bot.fxtun.ru
Forwarding to localhost:8080
Ready to receive connections
```

Имя `vk-bot` условное, выберите своё. На тарифах с инспектором перед последней строкой будет ещё `Inspector: http://127.0.0.1:4040`.

Страница-предупреждение, которую fxTunnel показывает в браузере на `*.fxtun.ru`, событиям не мешает: она бывает только у GET-запросов с HTML в ответе, а ВКонтакте шлёт POST.

## Шаг 4. Адрес в настройках сообщества

1. Откройте **Управление → Дополнительно → Работа с API**, вкладку **Callback API**.
2. Впишите адрес `https://vk-bot.fxtun.ru`.
3. Скопируйте строку подтверждения, которую показывает страница. Перезапустите обработчик с ней в `VK_CONFIRMATION`.
4. В поле **Секретный ключ** впишите то же, что в `VK_SECRET`.
5. Нажмите **Подтвердить**. В окне обработчика появится запрос с ответом `200`.
6. В настройках сервера выберите версию API, ту же, что в коде (в примере `5.199`).
7. После подтверждения откроются настройки уведомлений. Отметьте в них **Входящее сообщение**.

Теперь напишите сообществу из своего аккаунта. Бот ответит «Получил: …», а обработчик напечатает строку с вашим id. Историю запросов и ответов вашего сервера показывает вкладка **Запросы** в тех же настройках: если что-то не так, смотрите туда первым делом.

Строку подтверждения можно получить и методом [groups.getCallbackConfirmationCode](https://dev.vk.com/ru/method/groups.getCallbackConfirmationCode). Но документация предупреждает: строка из метода годится только для настройки сервера через API, в интерфейсе сообщества код будет другим.

## Когда адрес меняется

Без `--domain` каждый запуск `fxtunnel` даёт новый случайный поддомен. ВКонтакте об этом не знает и продолжает слать события на старый адрес, получает ошибки и через несколько неудач временно перестаёт отправлять. Сменить адрес — значит отредактировать сервер, а при правке настроек строка подтверждения меняется. Придётся взять новую строку, перезапустить обработчик и подтвердить адрес заново.

Поэтому адрес лучше держать постоянным. С флагом `--domain vk-bot` имя остаётся тем же на любом тарифе, но на бесплатном его может занять кто-то другой, пока ваш туннель выключен. Закрепить имя за собой можно с тарифа Base:

```bash
fxtunnel domains add vk-bot
```

Там же можно подключить свой домен вида `bot-dev.example.com`. Порядок по шагам описан в статье [«Постоянный адрес туннеля»](/blog/permanent-tunnel-address/).

Удобно держать отладочный адрес отдельным сервером Callback API. Серверов в сообществе может быть до 10, у каждого свои события, так что боевой сервер работает как работал, а на `vk-bot.fxtun.ru` приходят события для отладки. Удалить сервер можно и из обработчика: по документации ответ `remove` на любое уведомление удаляет сервер из настроек.

## Сертификат и проверка отправителя

Документация ВКонтакте советует загрузить клиентский SSL-сертификат, чтобы ваш сервер проверял, что запрос прислал именно ВКонтакте. Через туннель это не сработает: HTTPS для адресов `*.fxtun.ru` завершается на сервере fxTunnel, и до вашего обработчика запрос доходит обычным HTTP. Проверять клиентский сертификат некому.

Для отладки хватает секретного ключа. Держите его длинным и случайным и не публикуйте вместе с кодом. Обработчик в примере сравнивает его через `hmac.compare_digest` и отвечает `403` на всё, где `secret` не совпал.

## Повтор события без нового сообщения

Писать боту одно и то же после каждой правки кода утомительно. На тарифах с инспектором (с Base) запросы через туннель сохраняются в `http://127.0.0.1:4040`, и событие можно отправить обработчику повторно кнопкой Replay. Учтите, что пример пропускает уже обработанные `event_id`: после перезапуска обработчика набор `seen` пуст, и повтор пройдёт. Подробнее — в разборе [инспектора трафика](/blog/traffic-inspector-debug-requests/).

На бесплатном тарифе выручает `curl` с телом события, сохранённым из вывода или из вкладки **Запросы**:

```bash
curl -d @event.json http://127.0.0.1:8080/
```

## Long Poll: можно обойтись без туннеля

У ВКонтакте есть второй способ получать события: [Bots Long Poll API](https://dev.vk.com/ru/api/bots-long-poll/getting-started). Там события копятся на стороне ВКонтакте, а ваш бот сам запрашивает их: получает адрес сервера методом `groups.getLongPollServer` и держит запрос с ожиданием до 90 секунд. Формат событий тот же, что в Callback API.

Бот на Long Poll сам ходит к ВКонтакте, поэтому публичный адрес ему не нужен, и туннель тоже. Если бот живёт на вашем компьютере или вы только начинаете, это самый простой путь. Туннель нужен, когда рабочий бот построен на Callback API и вы отлаживаете именно этот обработчик: подтверждение, секретный ключ, ответы и повторы.

## Если события не приходят

**Адрес не подтверждается.** Обработчик вернул не ту строку: вы скопировали её до правки настроек, и она сменилась. Возьмите текущую строку во вкладке Callback API и перезапустите обработчик.

**Подтверждение прошло, события не идут.** Не отмечены типы событий, или сервер временно отключён после серии ошибок. Посмотрите вкладку **Запросы**.

**Обработчик отвечает `403`.** Секретный ключ в настройках сервера и в `VK_SECRET` отличается.

**`KeyError: 'message'`.** В настройках сервера версия API ниже 5.103, и сообщение пришло прямо в `object`. Выберите ту же версию, что в коде.

**Туннель перезапущен без `--domain`.** Адрес сменился, а в настройках остался старый. Верните прежнее имя или отредактируйте сервер и подтвердите заново.

**`send failed: … access_token`.** Ключ сообщества неверный или без доступа к сообщениям. Создайте новый с нужными правами.
