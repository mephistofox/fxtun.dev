Выделенный сервер Valheim без режима crossplay занимает два UDP-порта: указанный в параметре `-port` и следующий за ним, по умолчанию 2456 и 2457. Так пишет [официальное руководство Iron Gate](https://www.valheimgame.com/support/a-guide-to-dedicated-servers/). Если белого IP нет и друзья не могут подключиться к вашему серверу, откройте эти порты двумя UDP-туннелями fxTunnel, это тариф Base. Чтобы номера снаружи и внутри совпали, запустите сервер с `-port 20456` и откройте туннели `fxtunnel udp 20456 --remote-port 20456` и `fxtunnel udp 20457 --remote-port 20457`. Друзья заходят через «Join IP» по адресу `fxtun.ru:20456`. Ниже по шагам, плюс когда туннель не нужен вовсе и почему «не удаётся подключиться».

## Crossplay или прямое подключение

У выделенного сервера Valheim два способа связи с игроками, и от выбора зависит, нужен ли туннель.

**Crossplay** включается параметром `-crossplay`. Руководство Iron Gate пишет, что в этом режиме сервер передаёт данные через ретранслятор (relay), и проброс портов не нужен. Подключиться можно по публичному IP и порту, коду приглашения (join code) или через список серверов, но не по локальному адресу. Crossplay пускает игроков со всех платформ, включая Xbox. [Вики Valheim](https://valheim.fandom.com/wiki/Dedicated_servers) добавляет две оговорки:

- из-за лишнего перехода через ретранслятор игроки чаще сталкиваются с лагами, тайм-аутами и разрывами;
- при серых адресах регистрация сервера может не пройти, если другой абонент того же провайдера держит сервер Valheim на том же внешнем адресе и том же порту. Помогает выбор своего, редкого порта.

Если друзья играют с Xbox или в версию не из Steam, или crossplay вас устраивает, туннель не нужен: запускайте сервер с `-crossplay` и давайте друзьям код приглашения.

**Прямое подключение** работает без `-crossplay`. Тогда сервер использует сеть Steam, а игроки подключаются к нему напрямую, без ретранслятора. Видеть и открывать такой сервер могут только игроки Steam. Для прямого подключения из интернета серверу нужны открытые порты, а с серым IP их не открыть. Вот здесь туннель и нужен.

## Какие порты нужны

| Порт | Протокол | Зачем |
|---|---|---|
| значение `-port`, по умолчанию 2456 | UDP | игровой трафик |
| `-port` + 1, по умолчанию 2457 | UDP | порт запросов Steam (Steam Query) |

Официальное руководство: «Valheim uses the specified Port AND specified Port+1». Протокол и назначение портов расписаны в [вики, раздел Ingress](https://valheim.fandom.com/wiki/Dedicated_servers). Оба порта UDP, TCP серверу снаружи не нужен.

## Почему номера портов должны совпадать

Туннель fxTunnel выдаёт UDP-порт снаружи из диапазона 20001–30000. Без флагов сервер слушал бы 2456, а друзья стучались бы, скажем, на `fxtun.ru:20412`. Второй туннель получил бы номер, никак не связанный с первым, хотя Valheim ждёт, что порт запросов идёт следующим за игровым.

Как именно игра использует второй порт при входе через «Join IP», мы не проверяли. Поэтому убираем сам вопрос: запускаем сервер на порту из диапазона туннелей и просим у fxTunnel ровно такие же номера. Параметр `-port` это позволяет.

## Шаг 1. Установите выделенный сервер

Сервер бесплатный и ставится через Steam: в библиотеке включите в фильтре пункт «Инструменты» (Tools), найдите Valheim Dedicated Server и установите. На Linux и без клиента Steam подойдёт SteamCMD, номер приложения 896660 ([вики](https://valheim.fandom.com/wiki/Dedicated_servers)):

```text
login anonymous
app_update 896660 validate
quit
```

Папку сервера откроет правый клик по Valheim Dedicated Server в библиотеке, «Управление» → «Просмотреть локальные файлы».

## Шаг 2. Параметры запуска

Сервер запускается скриптом `start_headless_server.bat` на Windows или `start_server.sh` на Linux. Руководство Iron Gate советует сделать копию скрипта и править её: оригинал Steam перезаписывает при каждом обновлении.

В копии найдите строку, которая запускает сервер (в поставляемом файле она начинается со `start valheim_server`), и задайте в ней параметры. Вот пример строки из вики с нашими значениями:

```bat
valheim_server.exe -nographics -batchmode -name "Friends" -port 20456 -world "Dedicated" -password "придумайте-пароль" -public 0
```

На Linux строка та же, только файл `./valheim_server.x86_64`.

Что значат параметры, по руководству:

- `-name` — имя сервера в списке;
- `-port 20456` — игровой порт; сервер займёт 20456 и 20457;
- `-world` — имя мира: новый создастся, существующий загрузится;
- `-password` — пароль для входа;
- `-public 0` — сервер не виден в общем списке, зайти можно только через кнопку «Join IP». Список нам и не нужен: друзья будут входить по адресу туннеля.

Если в строке есть `-crossplay`, уберите его. Вики пишет, что в поставляемых скриптах он стоит по умолчанию, а с ним сервер уходит в режим ретранслятора, и туннель ему ни к чему.

Запустите скрипт. Сервер готов, когда в его окне появится `Game server connected`. Останавливайте его сочетанием Ctrl+C в окне сервера: руководство предупреждает, что после закрытия окна крестиком сервер может остаться работать в фоне, а вики — что при неправильной остановке теряется несохранённый прогресс.

## Шаг 3. Два туннеля

Установите клиент fxTunnel и войдите, это делается один раз. На Windows в PowerShell:

```powershell
irm https://fxtun.ru/install.ps1 | iex
```

На Linux и macOS:

```bash
curl -fsSL https://fxtun.ru/install.sh | sh
```

Затем в новом окне терминала:

```bash
fxtunnel login
```

Откройте туннели, каждый в своём окне терминала:

```bash
fxtunnel udp 20456 --remote-port 20456
```

```console
Connecting to fxtunnel server...
Tunnel established!
UDP: fxtun.ru:20456
Forwarding to localhost:20456
Inspector: http://127.0.0.1:4040
Ready to receive connections
```

```bash
fxtunnel udp 20457 --remote-port 20457
```

Второй туннель напечатает такие же строки с портом 20457. Строку `Inspector:` для игры можно не замечать, инспектор нужен HTTP-туннелям.

Если сервер работает постоянно, два окна неудобны. Опишите туннели в `fxtunnel.yaml` и поднимите их в фоне одной командой `fxtunnel up`:

```yaml
# fxtunnel.yaml
tunnels:
  - name: valheim-game
    type: udp
    local_port: 20456
    remote_port: 20456
  - name: valheim-query
    type: udp
    local_port: 20457
    remote_port: 20457
```

Подробнее, с автозапуском, рассказано в статье [«fxtunnel up: все туннели в фоне по одному конфигу»](/blog/fxtunnel-up-config/).

На бесплатном тарифе UDP-туннель не откроется:

```console
Failed to connect: server rejected tunnel: UDP tunnels are not available on your plan — upgrade to enable UDP
```

Это ответ сервера, а не сбой сети. UDP и несколько туннелей одновременно доступны с тарифа Base.

## Шаг 4. Подключение друзей

По [вики](https://valheim.fandom.com/wiki/Dedicated_servers) друг заходит так:

1. Запускает Valheim и выбирает персонажа.
2. В окне выбора мира открывает вкладку **Join Game** («Присоединиться»).
3. Нажимает **Join IP** и вписывает адрес с портом: `fxtun.ru:20456`.
4. Нажимает **Connect** и вводит пароль сервера.

Если игра не примет имя `fxtun.ru`, впишите вместо него IP-адрес: его покажет команда `nslookup -type=A fxtun.ru`. Порт остаётся тем же, `:20456`.

Вы сами подключаетесь к своему серверу по `127.0.0.1:20456`, если играете на том же компьютере, или по локальному адресу машины с сервером из домашней сети. Этот способ вики называет для игры на одном ПК с сервером.

## Если порт занят

Порт из диапазона получает тот, кто занял его первым. Если 20456 или 20457 уже у кого-то, клиент ответит:

```console
Failed to connect: server rejected tunnel: port 20456 is already in use
```

Выберите другую пару подряд идущих портов в диапазоне 20001–30000, например 20556 и 20557. Поменяйте `-port` в скрипте сервера, перезапустите его и откройте туннели на новые номера. Навсегда порт за аккаунтом не закрепляется, держите в запасе пару вариантов.

Без `--remote-port` сервер fxTunnel выдал бы первый свободный порт, а после перезапуска `fxtunnel` снова какой-то новый. Для Valheim, где номера идут парой, флаг обязателен.

## «Не удаётся подключиться к серверу»: частые причины

**Туннель открыт по TCP.** Valheim работает по UDP. Нужна команда `fxtunnel udp`, а не `fxtunnel tcp`.

**Открыт один туннель из двух.** Руководство прямо говорит, что сервер использует порт и порт+1. Проверьте, что работают оба туннеля.

**Номера не совпадают.** В скрипте `-port 20456`, а туннели открыты на другие порты, или порты не идут подряд. Сверьте `-port` и числа в командах `fxtunnel`.

**Сервер запущен с `-crossplay`.** В этом режиме игроки попадают на сервер через ретранслятор, который найден по вашему настоящему внешнему адресу, а адрес туннеля ему ничего не говорит. Либо уберите `-crossplay` и заходите через туннель, либо оставьте crossplay и давайте друзьям код приглашения.

**Друг играет не в Steam-версию.** Без crossplay сервер доступен только игрокам Steam. Для Xbox и других платформ нужен crossplay.

**Разные версии игры.** Сервер при подключении сверяет версию, так пишет вики. Обновите сервер через Steam или SteamCMD и игру у всех друзей.

**Сервер ещё загружается.** Пока в окне сервера нет строки `Game server connected`, подключения он не примет.

**Неверный пароль.** Пароль вводится в самой игре. Если друг заходит по ссылке `steam://connect`, Steam спросит пароль ещё и в своём окне, но вики отмечает, что работает только поле в игре.

## Кого пускать на сервер

Адрес туннеля публичный: кто знает `fxtun.ru:20456`, тот может постучаться. У Valheim свои средства защиты ([руководство Iron Gate](https://www.valheimgame.com/support/a-guide-to-dedicated-servers/)):

- `-password` — без пароля не войти;
- `adminlist.txt`, `bannedlist.txt` и `permittedlist.txt` в папке сохранений — администраторы, забаненные и разрешённые игроки, по одному ID платформы в строке. Руководство предупреждает: если добавить кого-то в `permittedlist.txt`, остальным вход закроется.

Списки работают по ID игрока, поэтому им не мешает то, что через туннель сервер видит всех игроков с локального адреса: пакеты ему передаёт клиент fxtunnel на той же машине.

У UDP-туннелей есть и флаг `--allow-ip`: сервер fxTunnel пропустит пакеты только с перечисленных адресов, остальные отбросит.

```bash
fxtunnel udp 20456 --remote-port 20456 --allow-ip 203.0.113.10 --allow-ip 198.51.100.0/24
```

Добавьте тот же список и ко второму туннелю. Если у друга меняется домашний IP, список придётся обновлять. Флага `--auth` у UDP-туннелей нет, он только для HTTP.
