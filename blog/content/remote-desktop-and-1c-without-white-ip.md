Чтобы подключиться к своему компьютеру через интернет, когда белого IP нет, откройте на нём TCP-туннель к порту удалённого рабочего стола: `fxtunnel tcp 3389 --allow-ip <ваш IP>`. Клиент выдаст адрес вида `fxtun.ru:13389`, и к нему подключается обычный клиент RDP (`mstsc` в Windows). Флаг `--allow-ip` пускает к порту только ваш адрес, остальные соединения сервер fxTunnel закрывает сразу. К базе 1С можно попасть двумя путями: зайти по RDP на компьютер, где она стоит, или опубликовать её на веб-сервере и открыть через HTTP-туннель в браузере.

Ниже по шагам, с мерами защиты: открытый в интернет RDP без них опасен.

## Как это устроено

Проброс порта на роутере требует белого IP. Туннель работает иначе: клиент `fxtunnel` на домашнем или офисном компьютере сам подключается к серверу fxTunnel, а сервер принимает подключения снаружи и передаёт их по этому соединению. Входящих соединений в вашу сеть не нужно, поэтому серый IP и CGNAT провайдера не мешают. Подробнее о сером IP — в статье [«Серый IP: как узнать и что делать»](/blog/grey-ip-what-to-do/).

## Шаг 1. Включите удалённый рабочий стол

Принимать подключения RDP могут выпуски Windows Pro, Enterprise, Education и Windows Server. Windows Home, по [документации Microsoft](https://learn.microsoft.com/ru-ru/windows-server/remote/remote-desktop-services/clients/remote-desktop-allow-access), подключаться к другим умеет, а к себе подключения не принимает. Если на нужном компьютере Home, этот путь не подойдёт.

На компьютере, к которому будете подключаться:

1. **Пуск → Параметры → Система → Удалённый рабочий стол**.
2. Включите **Удалённый рабочий стол** и подтвердите.
3. В тех же настройках оставьте включённой проверку подлинности на уровне сети (NLA). Microsoft рекомендует держать её включённой: пользователь проходит проверку ещё до того, как для него создаётся сеанс.
4. Если входить будет не администратор, добавьте его в список пользователей удалённого рабочего стола.

Служба слушает порт 3389 по TCP.

## Шаг 2. Узнайте свой внешний IP

Главная защита туннеля — список разрешённых адресов. Нужен внешний IPv4-адрес того места, **откуда** вы будете подключаться: ноутбука в гостинице, рабочего компьютера, дачи. Там откройте любой сайт проверки IP или выполните в терминале:

```powershell
curl.exe -4 ifconfig.me
```

На Windows пишите именно `curl.exe`: в Windows PowerShell 5.1 слово `curl` — псевдоним другой команды. На Linux и macOS — просто `curl -4 ifconfig.me`.

Нужен именно IPv4: посетители приходят на `fxtun.ru` по IPv4. В примерах ниже это `203.0.113.10`.

## Шаг 3. Туннель

На компьютере с удалённым рабочим столом установите клиент. В PowerShell:

```powershell
irm https://fxtun.ru/install.ps1 | iex
```

На Linux и macOS установка другая: `curl -fsSL https://fxtun.ru/install.sh | sh`. Затем в новом окне терминала войдите в аккаунт:

```bash
fxtunnel login
```

Откройте туннель:

```bash
fxtunnel tcp 3389 --remote-port 13389 --allow-ip 203.0.113.10 --max-lifetime 8h
```

```console
Connecting to fxtunnel server...
Tunnel established!
TCP: fxtun.ru:13389
Forwarding to localhost:3389
IP Allowlist: 1 entry
Max lifetime: 8h
Ready to receive connections
```

Что делают флаги:

- `--remote-port 13389` просит конкретный порт снаружи. Без него сервер выдаст первый свободный из диапазона 10000–20000, а после перезапуска `fxtunnel` порт будет новым. Если 13389 уже занят кем-то другим, клиент ответит `Failed to connect: server rejected tunnel: port 13389 is already in use`; выберите другой номер в том же диапазоне. Навсегда за аккаунтом порт не закрепляется.
- `--allow-ip` пропускает только перечисленные адреса и подсети, флаг можно повторить. С любого другого адреса сервер fxTunnel закроет соединение, до вашего компьютера оно не дойдёт.
- `--max-lifetime 8h` закроет туннель через восемь часов, даже если вы про него забудете.

TCP-туннель работает на бесплатном тарифе. Окно с туннелем не закрывайте, пока нужен доступ.

## Шаг 4. Подключение

На компьютере, с которого подключаетесь, нажмите Win+R и запустите `mstsc`. В поле **Компьютер** введите адрес вместе с портом:

```text
fxtun.ru:13389
```

Или сразу из командной строки:

```bash
mstsc /v:fxtun.ru:13389
```

Дальше обычный вход: имя пользователя и пароль учётной записи Windows. С macOS, iOS и Android подключаются приложением Windows App от Microsoft, адрес тот же.

## Защита: что сделать до того, как открыть порт

Открытый в интернет порт RDP находят сканеры и начинают подбирать пароли. У TCP-туннеля нет пароля на своей стороне: `--auth` работает только у HTTP-туннелей. Поэтому защита складывается из нескольких слоёв.

**1. Список IP.** `--allow-ip` — главная мера. Подбор пароля невозможен, если соединение не доходит до Windows. Слабое место одно: мобильный интернет и общий NAT оператора, где за одним адресом сотни абонентов. Разрешили такой адрес — пустили их всех. Подробно о списках — в статье [«Пароль и список IP для туннеля»](/blog/tunnel-password-and-ip-allowlist/).

**2. NLA.** Не отключайте её. Без NLA сервер показывает экран входа любому, кто подключился.

**3. Сложный пароль.** Microsoft прямо пишет: у всех учётных записей с удалённым доступом должны быть надёжные уникальные пароли. Короткий словарный пароль перебирается автоматически.

**4. Блокировка учётной записи после неудачных попыток.** Политика **Пороговое значение блокировки** задаёт, после скольких неверных паролей учётная запись блокируется. Она лежит в `secpol.msc` → **Политики учётных записей → Политика блокировки учётной записи**. Базовые настройки безопасности Windows советуют начинать с 10 попыток ([Microsoft, Account lockout threshold](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-10/security/threat-protection/security-policy-settings/account-lockout-threshold)). Задать её можно и командой в командной строке администратора:

```powershell
net accounts /lockoutthreshold:10
```

Важная деталь из той же документации: встроенная учётная запись «Администратор» под эту политику не попадает. Входите по RDP под обычной учётной записью с правами на удалённый доступ.

**5. Временный туннель.** `--max-lifetime` закрывает туннель через заданное время, `--auto-close 30m` — после получаса без трафика. Пока вы работаете в сеансе, данные идут и туннель живёт. Подробнее — в статье [«Временные туннели»](/blog/temporary-tunnels-auto-close/).

Одна особенность туннеля: Windows видит все подключения с адреса `127.0.0.1`, ведь их передаёт клиент `fxtunnel` на этой же машине. В журнале событий настоящего адреса подключившегося не будет. Отсекать чужих по адресу — задача `--allow-ip` на сервере fxTunnel.

## 1С удалённо: два пути

### Путь 1. RDP на компьютер с базой

Самый простой вариант: 1С уже установлена на компьютере с базой, вы подключаетесь к нему по RDP, как выше, и запускаете 1С в удалённом сеансе. Отдельной настройки 1С не нужно, база никуда не публикуется, наружу открыт только защищённый списком IP порт RDP. Для одного человека, которому надо поработать в базе из дома, это обычно лучший выбор.

### Путь 2. Веб-публикация базы

«1С:Предприятие» умеет работать с базой через веб-сервер Apache или IIS, на котором база заранее опубликована ([руководство 1C:EDT на ИТС](https://its.1c.ru/db/content/edtdoc/src/topics/t000325.html)). По тому же руководству при публикации из 1C:EDT по умолчанию публикуются тонкий клиент, веб-клиент, интерфейс OData, веб-сервисы и HTTP-сервисы конфигурации. Веб-клиент — это 1С в обычном браузере, без установки программы.

Порядок такой:

1. Установите на компьютер с базой веб-сервер Apache или IIS.
2. Откройте базу в конфигураторе и выберите пункт **Публикация на веб-сервере…** в меню **Администрирование**. Задайте имя публикации и нажмите **Опубликовать** ([методическая поддержка 1С на ИТС](https://its.1c.ru/db/content/metod81/src/appsolutionselffinanced/small%20business/crm/telephony/i8106966.htm)). Эта же статья ИТС отсылает за подробной настройкой веб-серверов к документации платформы «1С:Предприятие 8»; на ИТС она открыта только по подписке.
3. Проверьте публикацию локально: в браузере на этом же компьютере откройте `http://localhost/<имя публикации>`.

Веб-сервер отвечает по HTTP, обычно на порту 80 или 8080. Его открывают HTTP-туннелем, и тут появляются сразу две защиты:

```bash
fxtunnel http 80 --domain my1c --allow-ip 203.0.113.10 --auth office:Long-Pass-2026x
```

```console
Connecting to fxtunnel server...
Tunnel established!
HTTP:  http://my1c.fxtun.ru
HTTPS: https://my1c.fxtun.ru
Forwarding to localhost:80
Basic Auth: enabled
IP Allowlist: 1 entry
Ready to receive connections
```

Теперь база открывается в браузере по адресу `https://my1c.fxtun.ru/<имя публикации>`. Сначала сервер fxTunnel проверит адрес по списку, затем спросит логин и пароль туннеля, и только потом запрос дойдёт до веб-сервера и 1С со своим входом.

Что стоит знать про этот путь:

- **Страница-предупреждение.** При первом заходе браузер увидит предупреждение fxTunnel о том, что сайт работает через туннель. Кнопка «Продолжить» убирает его на 12 часов. На своём домене этой страницы нет.
- **`--auth` и вход 1С.** Basic Auth передаёт логин и пароль туннеля в заголовке `Authorization`, и этот заголовок доходит до веб-сервера. Как публикация 1С поступит с чужим заголовком, зависит от её настроек аутентификации; мы это не проверяли. Если после пароля туннеля 1С не пускает, уберите `--auth` и оставьте `--allow-ip`.
- **Тонкий клиент.** Он тоже умеет работать через веб-сервер, но это не браузер. Справится ли он с паролем туннеля и страницей-предупреждением, мы не проверяли. Надёжнее открыть для него туннель без `--auth`, только со списком IP, и на своём домене, где предупреждения нет.
- **Поддомен.** Без `--domain` каждый запуск даёт новый случайный адрес. С `--domain my1c` адрес постоянный, пока имя никто не занял. Закрепить имя за собой можно с тарифа Base, там же подключается свой домен вида `1c.example.com` ([«Постоянный адрес туннеля»](/blog/permanent-tunnel-address/)).

Мы описываем только эти два пути. Прямое подключение тонкого клиента к кластеру серверов 1С через туннель здесь не разбираем.

## Когда нужен второй туннель

На бесплатном тарифе одновременно работает один туннель. Второй клиент на том же аккаунте получит отказ:

```console
Failed to connect: server rejected tunnel: tunnel limit reached
```

Это ответ сервера, а не сбой сети. Второй туннель нужен, например, когда:

- кроме RDP, открыта веб-публикация 1С;
- вы подключаетесь к двум компьютерам: домашнему и офисному;
- рядом с RDP нужен доступ к NAS или камере.

Тариф Base даёт пять туннелей одновременно, резерв поддоменов и свой домен. Несколько туннелей удобно описать в файле и поднимать одной командой, как рассказано в статье [«fxtunnel up: все туннели в фоне по одному конфигу»](/blog/fxtunnel-up-config/). Если командная строка не нравится, туннели можно открывать и в {{< later "fxtunnel-gui-client" >}}GUI-клиенте fxTunnel{{< /later >}}.

## Если не подключается

**`mstsc` пишет, что не удаётся подключиться.** Проверьте, что окно с туннелем открыто и в нём есть `Ready to receive connections`. Сверьте порт в `mstsc` с портом в строке `TCP:`.

**Соединение сразу обрывается.** Скорее всего, ваш текущий адрес не в списке `--allow-ip`: сервер fxTunnel закрывает такие соединения сразу. Узнайте адрес заново (`curl.exe -4 ifconfig.me` на Windows) и перезапустите туннель. Домашние провайдеры время от времени меняют внешний IP.

**Порт другой, чем вчера.** Туннель перезапускали без `--remote-port`. Задайте порт явно.

**Windows отвечает, что удалённые подключения запрещены.** Удалённый рабочий стол выключен, пользователь не в списке разрешённых или на компьютере Windows Home.

**Учётная запись заблокирована.** Сработала политика неудачных попыток. Это она и должна делать, но ещё это признак, что кто-то подбирал пароль. Проверьте список IP и смените пароль.
