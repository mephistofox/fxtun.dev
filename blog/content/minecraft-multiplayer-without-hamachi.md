Поиграть в Майнкрафт по сети с другом из другого города можно без Хамачи, без Radmin VPN и без белого IP. Нужна одна команда на вашем компьютере: `fxtunnel tcp 25565`. Она выдаёт адрес вида `fxtun.ru:14215`, вы отправляете его другу, он вставляет адрес в «Сетевую игру» и заходит в ваш мир. Ставить ему ничего не надо, открывать порты на роутере тоже. Для Java Edition хватает бесплатного тарифа.

Ниже разберём по шагам: как запустить мир, как открыть к нему доступ, почему адрес иногда меняется и что делать, если друг видит «Не удалось подключиться».

## Три способа играть вместе

Когда вы с другом сидите в одной квартире на одном Wi-Fi, всё просто: «Открыть для сети», и его игра сама находит ваш мир. Через интернет эта кнопка не работает. Ваш компьютер спрятан за роутером, а часто ещё и за оборудованием провайдера, и чужая игра до него не дотягивается.

Вариантов обычно три.

**Открыть мир в LAN и позвать друга в общую виртуальную сеть.** Так работают Хамачи и Radmin VPN: обе программы создают виртуальную локальную сеть поверх интернета. Способ рабочий, но программу ставят все игроки, все вступают в одну сеть, а если у кого-то она не завелась, вечер уходит на выяснение, чья сеть сломалась.

**Поднять выделенный сервер и открыть порт на роутере.** Классика. Только проброс порта работает, если у вас белый IP. Многие провайдеры выдают серый адрес за общим NAT, и тогда настройки роутера ничего не дадут. Как это проверить, расскажет {{< later "grey-ip-what-to-do" >}}статья про серый IP{{< /later >}}.

**Открыть мир или сервер через туннель.** Клиент на вашем компьютере сам подключается к серверу fxTunnel, а тот выдаёт публичный адрес. Друг подключается к этому адресу как к обычному серверу Майнкрафта.

| | Хамачи / Radmin VPN | Проброс порта | Туннель |
|---|---|---|---|
| Что ставит друг | Ту же программу | Ничего | Ничего |
| Нужен белый IP | Нет | Да | Нет |
| Настройка роутера | Нет | Да | Нет |
| Что вы отправляете другу | Имя сети и пароль | Свой IP и порт | Адрес `fxtun.ru:порт` |

Главное отличие туннеля от Хамачи простое: вся настройка на вашей стороне. Друг получает строчку с адресом и больше ничего не делает.

## Шаг 1. Установите клиент и войдите

Клиент fxTunnel — одна программа, ставится одной командой. На Windows откройте PowerShell (права администратора не нужны):

```powershell
irm https://fxtun.ru/install.ps1 | iex
```

На Linux и macOS:

```bash
curl -fsSL https://fxtun.ru/install.sh | sh
```

После установки откройте новое окно терминала и войдите в аккаунт:

```bash
fxtunnel login
```

Нажмите Enter: клиент откроет страницу входа в браузере и покажет код. Введите код на странице, подтвердите, и в терминале появится `Authorized!`. Аккаунт заводится на [fxtun.ru](https://fxtun.ru/register), вход нужен один раз.

## Шаг 2. Запустите мир

Подойдут оба варианта: обычный одиночный мир, открытый для сети, или отдельный сервер. Разница в том, что мир живёт, пока открыта ваша игра, а сервер работает сам по себе.

### Вариант А: «Открыть для сети»

Зайдите в свой мир, нажмите Esc и выберите «Открыть для сети». Игра напишет в чат номер порта. Его и нужно передать туннелю.

Есть подвох: если номер порта не задать, игра каждый раз выбирает его случайно. Об этом прямо сказано на [minecraft.wiki](https://minecraft.wiki/w/Open_to_LAN). Начиная с версии 1.19.3 в том же окне можно указать порт самому ([список изменений 1.19.3](https://minecraft.wiki/w/Java_Edition_1.19.3)). Впишите, например, `25565`, и команда туннеля будет одной и той же при каждой игре.

То же умеет команда `/publish`: у неё есть необязательный аргумент с портом ([minecraft.wiki](https://minecraft.wiki/w/Commands/publish)).

### Вариант Б: выделенный сервер

Скачайте `server.jar` с официального сайта и запустите его так, как советует [руководство на minecraft.wiki](https://minecraft.wiki/w/Tutorial:Setting_up_a_Java_Edition_server):

```bash
java -Xmx2G -jar server.jar --nogui
```

При первом запуске сервер создаст файл `eula.txt` и остановится. Откройте файл, замените `eula=false` на `eula=true` (так вы соглашаетесь с лицензией Minecraft) и запустите сервер снова.

Сервер слушает TCP-порт из параметра `server-port` в файле `server.properties`, по умолчанию `25565` ([minecraft.wiki](https://minecraft.wiki/w/Server.properties)). Оставьте его как есть.

## Шаг 3. Откройте туннель

В отдельном окне терминала:

```bash
fxtunnel tcp 25565
```

Если вы открывали мир для сети со случайным портом, подставьте номер из чата: `fxtunnel tcp 51234`.

Клиент покажет адрес:

```console
Connecting to fxtunnel server...
Tunnel established!
TCP: fxtun.ru:14215
Forwarding to localhost:25565
Ready to receive connections
```

Строка `TCP: fxtun.ru:14215` — адрес для друга. Порт у вас будет свой, из диапазона 10000–20000. Окно с туннелем не закрывайте: туннель работает, пока запущен клиент, а остановить его можно клавишами `Ctrl+C`.

Друг заходит в Minecraft, открывает «Сетевую игру» и выбирает «Прямое подключение» (или «Добавить сервер», чтобы сохранить адрес в списке). В поле адреса он пишет `fxtun.ru:14215`, целиком, с двоеточием и портом. Готово: он в вашем мире.

{{< note type="info" >}}
Друг подключается к серверу fxTunnel, а не к вашему домашнему адресу. Ваш IP он не видит, а в вашей сети ничего открывать не нужно.
{{< /note >}}

## Почему порт меняется и как его удержать

Сыграли вечер, выключили компьютер, на следующий день запустили `fxtunnel tcp 25565` снова. Адрес может оказаться другим, например `fxtun.ru:14216`. Это нормально: сервер выдаёт первый свободный порт из диапазона, и после перезапуска клиента ваш прошлый порт уже может быть занят кем-то другим. Пока клиент работает, порт за вами держится: если пропадёт интернет, клиент переподключится и получит тот же номер.

Есть два способа жить с этим.

**Отправлять другу новый адрес.** Самый простой вариант. Одна строчка в мессенджере.

**Попросить конкретный порт.** Флаг `--remote-port` задаёт номер на сервере, но только из диапазона 10000–20000:

```bash
fxtunnel tcp 25565 --remote-port 15565
```

Если порт свободен, адрес будет `fxtun.ru:15565` при каждом запуске, и друг может сохранить его в списке серверов. Если же порт занят другим пользователем, клиент откажет с `Failed to connect: server rejected tunnel: port 15565 is already in use`, и нужно выбрать другой. Запросить `--remote-port 25565` нельзя: номер вне диапазона, сервер ответит `outside allowed range`.

Порт не закрепляется за вашим аккаунтом навсегда. Кто первым занял номер, того он и есть, поэтому держите в запасе пару вариантов.

## Если друг не может подключиться

Чаще всего всё решается одним из пунктов ниже.

**Адрес без порта.** Если друг ввёл просто `fxtun.ru`, игра постучится в стандартный порт 25565, а там вашего мира нет. Адрес вводится целиком: `fxtun.ru:14215`.

**Порт туннеля не совпадает с портом мира.** Для «Открыть для сети» без выбранного порта это главная ловушка: вы заново открыли мир, игра выбрала новый порт, а туннель смотрит на старый. Сверьте номер в чате игры с числом в команде `fxtunnel tcp`.

**Туннель или мир закрыты.** Вы закрыли окно терминала, вышли из мира в меню или компьютер ушёл в сон — адрес перестаёт отвечать. Для долгих сессий удобнее выделенный сервер и отключённый спящий режим.

**Разные версии игры.** Сервер Java Edition пускает клиентов своей версии. Если у вас 1.21.1, а у друга другая версия, он получит сообщение об устаревшем клиенте или сервере. Выберите одну версию в лаунчере.

**Брандмауэр и антивирус.** При первом запуске сервера Windows спрашивает, разрешить ли Java доступ к сети. Для туннеля это не главное: клиент fxtunnel подключается к игре на этом же компьютере. Если клиент пишет `Failed to connect:` — смотрите, что написано после двоеточия. Отказ сервера (`server rejected tunnel: ...`) объясняет причину прямо в тексте; сетевая ошибка без такого отказа — повод проверить, не блокирует ли антивирус или брандмауэр программу `fxtunnel`.

**Уже открыт другой туннель.** На бесплатном тарифе одновременно работает один туннель. Если в соседнем окне запущен ещё один, новый не откроется: клиент откажет с `Failed to connect: server rejected tunnel: tunnel limit reached`.

### online-mode и лаунчеры

В `server.properties` есть параметр `online-mode`, по умолчанию `true`. С ним сервер пускает только игроков, чей аккаунт подтверждён базой аккаунтов Minecraft ([minecraft.wiki](https://minecraft.wiki/w/Server.properties)). Лаунчер без такого аккаунта сервер отклонит.

Параметр можно выключить, но тогда сервер не проверяет, кто прячется за ником. Любой, кто узнает адрес, сможет зайти под вашим именем, в том числе с правами оператора. Это решение владельца сервера, и принимать его стоит осознанно: держите адрес при себе и закрывайте туннель, когда не играете.

С включённым `online-mode` добавьте белый список: `/whitelist on`, затем `/whitelist add НикДруга`. Тогда на сервер попадут только те, кого вы позвали, даже если адрес где-то утёк ([minecraft.wiki](https://minecraft.wiki/w/Commands/whitelist)).

## А если друг играет на телефоне или консоли

Java Edition и Bedrock Edition — разные игры с разными серверами. Bedrock стоит на телефонах, консолях и в версии из Microsoft Store, а его сервер слушает UDP-порт 19132 ([minecraft.wiki](https://minecraft.wiki/w/Server.properties)). Команда там другая: `fxtunnel udp 19132`, а UDP-туннели работают с тарифа Base. Подробности — в {{< later "minecraft-bedrock-server-friends" >}}отдельной статье про сервер Bedrock для друзей{{< /later >}}.

## Когда одного туннеля мало

Бесплатного тарифа хватает на один мир: один туннель, один порт. Хотите держать сразу выживание и мини-игры, или карту для друзей плюс сайт с её рендером, — понадобится несколько туннелей одновременно:

```bash
fxtunnel tcp 25565
fxtunnel tcp 25566
```

Каждая команда запускается в своём окне и получает свой адрес. На тарифе Base одновременно работают пять туннелей, и среди них могут быть UDP — для Bedrock и других игр, где UDP обязателен.
