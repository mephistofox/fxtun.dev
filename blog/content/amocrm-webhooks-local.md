Вебхук amoCRM — это POST-запрос, который amoCRM отправляет на ваш адрес, когда в аккаунте что-то происходит: добавили сделку, сменился её статус, изменили контакт. Адрес должен быть доступен из интернета, `localhost` amoCRM не достанет. Чтобы принимать вебхуки на своём компьютере во время разработки, запустите обработчик на `localhost:8080`, откройте туннель `fxtunnel http 8080` и укажите выданный HTTPS-адрес в настройках вебхука в разделе амоМаркет.

Ниже по шагам: что и в каком виде присылает amoCRM, обработчик на Python, настройка, правило двух секунд и отладка без бесконечного перетаскивания сделок.

## Что говорит документация

Всё в этом разделе — из [документации amoCRM о формате вебхуков](https://www.amocrm.ru/developers/content/crm_platform/webhooks-format).

**Где настраивается.** В разделе **амоМаркет**, кнопка **WEB HOOKS** в правом верхнем углу. Там задаются URL и события, затем **Сохранить**.

**Сущности:** сделка, контакт, компания, покупатель, задача, список, беседы, шаблоны WhatsApp.

**События:** добавление, изменение, удаление, восстановление (для сделки, контакта, компании), смена статуса (для сделки), смена ответственного, добавление примечания (для сделки, контакта, компании, покупателя), отправка шаблона WhatsApp на одобрение. Уточнения в скобках — как в документации.

**Формат.** Вебхук отправляется в формате `x-www-form-urlencoded`. Внутри — массив вида `{"сущность": {"действие": {"0": {поля сущности}}}}` при создании и изменении и `{"сущность": {"действие": "id"}}` при удалении. Пример из документации для смены статуса сделки, в сокращении:

```json
{
  "leads": {
    "status": {
      "0": {
        "id": "25399013",
        "name": "Lead title",
        "old_status_id": "7039101",
        "status_id": "142",
        "account_id": "7039099"
      }
    }
  }
}
```

**Ответ.** amoCRM ждёт ответа не больше 2 секунд. Запрос считается принятым, если код ответа от 100 до 299. Нет ответа за 2 секунды или код другой — вебхук считается недоставленным, а отклик невалидным.

**Повторы.** Первая попытка идёт сразу после события. Если она неудачна, amoCRM повторяет:

| Попытка | Через сколько после предыдущей | Если предыдущая ответила |
|---|---|---|
| 2 | 5 минут | 0–99, 300 и больше |
| 3 | 15 минут | 0–99, 300 и больше |
| 4 | 15 минут | 499 или 500–599 |
| 5 | 1 час | 499 или 500–599 |

**Отключение.** Если за последние 2 часа пришло больше 100 невалидных откликов и последний тоже невалидный, amoCRM отключит вебхук и пришлёт уведомление администраторам. Включить его обратно можно в настройках кнопкой **Включить** и сохранением.

Последнее правило важно именно при разработке. Вы остановили обработчик, а сделки в аккаунте продолжают двигаться. Каждое событие — невалидный отклик. Работаете в живом аккаунте с потоком событий — рискуете потерять вебхук. Для разработки лучше отдельный тестовый вебхук, который вы включаете на время работы.

## Как форма превращается в массив

Документация показывает данные как JSON, а по сети они идут полями формы. Ключи формы документация не показывает. Обработчик ниже рассчитан на распространённую запись вложенных массивов в квадратных скобках, `leads[status][0][id]=25399013`, и собирает из неё словарь, как в документации. Это предположение: проверьте ключи в инспекторе или в выводе обработчика на первом же событии, прежде чем писать логику. Список полей у разных сущностей к тому же разный.

## Шаг 1. Обработчик

Обработчик на стандартной библиотеке Python. Он принимает POST только на секретный путь, отказывает телам больше 1 МБ (`413`) и формам, которые не складываются в словарь (`400`), сразу отвечает `200` и печатает разобранное событие:

```python
# amo_hook.py
import hmac
import json
import os
from http.server import BaseHTTPRequestHandler, HTTPServer
from urllib.parse import parse_qsl

HOOK_PATH = os.environ["AMO_HOOK_PATH"]
MAX_BODY = 1024 * 1024  # 1 МБ


def nest(pairs):
    """leads[status][0][id]=1 -> {"leads": {"status": {"0": {"id": "1"}}}}"""
    root = {}
    for key, value in pairs:
        parts = key.replace("]", "").split("[")
        node = root
        for part in parts[:-1]:
            node = node.setdefault(part, {})
            if not isinstance(node, dict):
                raise ValueError(f"conflicting key {key}")
        if isinstance(node.get(parts[-1]), dict):
            raise ValueError(f"conflicting key {key}")
        node[parts[-1]] = value
    return root


class Hook(BaseHTTPRequestHandler):
    def reply(self, code):
        self.send_response(code)
        self.send_header("Content-Length", "0")
        self.end_headers()

    def do_POST(self):
        if not hmac.compare_digest(self.path.encode(), HOOK_PATH.encode()):
            return self.reply(404)
        length = int(self.headers.get("Content-Length", 0))
        if length > MAX_BODY:
            return self.reply(413)
        raw = self.rfile.read(length)
        try:
            data = nest(parse_qsl(raw.decode(errors="replace"), keep_blank_values=True))
        except ValueError:
            return self.reply(400)
        self.reply(200)
        print(json.dumps(data, ensure_ascii=False, indent=2), flush=True)


HTTPServer(("127.0.0.1", 8080), Hook).serve_forever()
```

Почему секретный путь. Адрес туннеля публичный, и в документации формата вебхуков нет подписи запроса, по которой можно отличить настоящий вебхук от поддельного. Самое простое, что можно сделать, — адрес, который нельзя угадать. Придумайте случайную строку:

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(16))"
```

И запустите обработчик с ней, например:

```bash
AMO_HOOK_PATH=/amo/Xq3v9KfT2mLw8RzA python3 amo_hook.py
```

На Windows в PowerShell: `$env:AMO_HOOK_PATH="/amo/Xq3v9KfT2mLw8RzA"; python amo_hook.py`.

Путь храните как пароль: он даёт право слать события в ваш код. Запросы на любой другой путь получают `404`. Путь сравнивается через `hmac.compare_digest`, за постоянное время.

## Шаг 2. Туннель

Установите клиент и войдите (один раз):

```bash
curl -fsSL https://fxtun.ru/install.sh | sh
fxtunnel login
```

На Windows вместо первой строки выполните в PowerShell `irm https://fxtun.ru/install.ps1 | iex`.

Во втором окне терминала откройте туннель. Имя поддомена задайте сразу, чтобы не менять URL в amoCRM после каждого перезапуска:

```bash
fxtunnel http 8080 --domain amohook
```

```console
Connecting to fxtunnel server...
Tunnel established!
HTTP:  http://amohook.fxtun.ru
HTTPS: https://amohook.fxtun.ru
Forwarding to localhost:8080
Inspector: http://127.0.0.1:4040
Ready to receive connections
```

Имя `amohook` условное, выберите своё. Строка `Inspector:` появляется на тарифах с инспектором, на бесплатном её не будет.

## Шаг 3. Вебхук в amoCRM

1. Откройте раздел **амоМаркет** и нажмите **WEB HOOKS** в правом верхнем углу.
2. Введите URL: `https://amohook.fxtun.ru/amo/Xq3v9KfT2mLw8RzA`, с вашим поддоменом и путём.
3. Отметьте события, например смену статуса сделки.
4. Нажмите **Сохранить**.

Вебхуки можно создавать и через API: `POST /api/v4/webhooks` с полями `destination` (URL) и `settings` (список событий, например `["add_lead"]`). Метод доступен с правами администратора аккаунта ([документация API вебхуков](https://www.amocrm.ru/developers/content/crm_platform/webhooks-api)). Для разработки хватает интерфейса.

## Шаг 4. Проверка

Перетащите сделку в другой этап воронки. Если ключи формы устроены так, как предполагает обработчик, в его окне появится событие:

```console
{
  "leads": {
    "status": {
      "0": {
        "id": "25399013",
        "status_id": "142",
        "old_status_id": "7039101",
        …
```

Из `id` берут номер сделки, из `status_id` и `old_status_id` — новый и старый этапы. Полей в настоящем событии больше, чем в сокращённом примере. Если вместо вложенного словаря вы видите плоские ключи другого вида или ответ `400`, откройте запрос в инспекторе и поправьте разбор под то, что пришло.

## Правило двух секунд

amoCRM ждёт ответа не больше 2 секунд. Обработчик выше сначала отвечает `200` и только потом печатает событие. В настоящем коде порядок тот же: принять, ответить, а тяжёлую работу — запрос в API amoCRM за полными данными, запись в базу, отправку письма — делать после ответа или в фоновой очереди.

Туннель добавляет к запросу путь от сервера fxTunnel до вашего компьютера и обратно. Если обработчик и так работает на грани двух секунд, на локальной машине он может не уложиться, и amoCRM запишет отклик как невалидный. Ещё одна причина отвечать сразу.

Будьте готовы и к повторам: при ошибке или медленном ответе то же событие придёт снова, через 5 минут и позже. Если обработчик что-то создаёт по событию, проверяйте, не обработано ли оно уже, например по `id` и `last_modified` сущности.

## Постоянный адрес

Без `--domain` каждый запуск `fxtunnel http 8080` даёт новый случайный поддомен, а amoCRM продолжает слать события на старый. Все они станут невалидными откликами, а это прямая дорога к отключению вебхука. Флаг `--domain amohook` решает это на любом тарифе, но пока туннель выключен, имя может занять кто-то другой.

Чтобы имя принадлежало только вам, зарезервируйте его:

```bash
fxtunnel domains add amohook
```

```console
Reserved: amohook → https://amohook.fxtun.ru
```

Резерв доступен с тарифа Base. Подробности и свой домен — в статье [«Постоянный адрес туннеля»](/blog/permanent-tunnel-address/).

## Отладка: повторить событие без правки сделки

Каждый раз двигать сделку по воронке, чтобы проверить исправленный код, утомительно. Инспектор fxTunnel избавляет от этого. Откройте `http://127.0.0.1:4040` в браузере: там каждый запрос, пришедший через туннель, с заголовками, телом формы и ответом обработчика. Кнопка Replay отправляет сохранённый запрос в ваш локальный обработчик ещё раз, минуя сервер fxTunnel и amoCRM ([документация инспектора](https://fxtun.ru/docs/inspector)).

Порядок работы:

1. Один раз двигаете сделку, событие приходит и сохраняется в инспекторе.
2. Правите обработчик и перезапускаете его.
3. Нажимаете Replay. Обработчик получает то же тело формы на тот же путь.

Повтор идёт только в ваш код, amoCRM о нём не знает, и невалидные отклики в её счётчик не попадают. Инспектор слушает только `127.0.0.1` и доступен с тарифа Base. На бесплатном тарифе выручает печать события в самом обработчике. Подробнее о фильтрах и API инспектора — в статье [«Traffic Inspector: отладка HTTP-запросов»](/blog/traffic-inspector-debug-requests/).

## Если событие не приходит

**Обработчик отвечает 404.** Путь в URL вебхука не совпадает с `AMO_HOOK_PATH`. Сверьте их посимвольно.

**Туннель открыт на другой порт.** Число в `fxtunnel http 8080` должно совпадать с портом обработчика.

**Адрес устарел.** Туннель перезапустили без `--domain`, и поддомен стал другим. Запускайте туннель с тем же именем или поправьте URL в настройках вебхука.

**Вебхук отключён.** Набралось больше 100 невалидных откликов за 2 часа. Включите вебхук в настройках кнопкой **Включить** и сохраните.

**Выбрано не то событие.** Вебхук на смену статуса сделки не сработает, когда вы меняете контакт. Проверьте список событий.
