Короткие ответы на частые вопросы. Подробности — по ссылкам в ответах.

## Как получить постоянный адрес?

Зарезервируйте поддомен и запускайте туннель с ним:

```bash
fxtunnel domains add myapp
fxtunnel http 3000 --domain myapp
→ HTTPS: https://myapp.fxtun.ru
```

Без резерва поддомен свободен для других, пока ваш туннель выключен. Подробнее — [«Поддомены»](/docs/subdomains).

## Как открыть доступ только коллегам?

Есть три способа, их можно сочетать.

Пароль:

```bash
fxtunnel http 3000 --auth team:SharedPass123
```

Список разрешённых адресов:

```bash
fxtunnel http 3000 --allow-ip 203.0.113.10
```

Случайный пароль, который клиент придумает сам и покажет при запуске:

```bash
fxtunnel http 3000 --preset openclaw
```

Подробнее — [«HTTP-туннели»](/docs/http).

## Как открыть сервис из Docker-контейнера?

Опубликуйте порт контейнера на компьютере и откройте туннель к нему:

```bash
docker run -d -p 8080:80 nginx
fxtunnel http 8080
```

В Linux можно обойтись без публикации порта: укажите адрес контейнера в `local_addr` [конфигурационного файла](/docs/config):

```yaml
tunnels:
  - name: docker-app
    type: http
    local_addr: 172.17.0.2
    local_port: 80
```

## Как отлаживать вебхуки?

1. Откройте туннель с постоянным поддоменом: `fxtunnel http 3000 --domain webhooks`.
2. Укажите в настройках сервиса адрес `https://webhooks.fxtun.ru/<путь>`.
3. Откройте инспектор по адресу из строки `Inspector:` — входящие запросы появятся там в реальном времени.

Предупредительная страница вебхукам не мешает: она показывается только на `GET`-запросы с HTML-ответом. Сохранённый запрос можно отправить повторно через API инспектора — [«Инспектор трафика»](/docs/inspector).

## Работает ли WebSocket?

Да, WebSocket проходит через HTTP-туннель без дополнительных настроек.

## Как запускать туннели вместе с системой?

Опишите туннели в `fxtunnel.yaml` и запускайте `fxtunnel up --foreground` как службу systemd. Готовый файл службы — в разделе [«Daemon-режим»](/docs/daemon).

## Как работать на сервере без хранилища паролей?

На серверах без графической оболочки системного хранилища паролей обычно нет. Тогда `fxtunnel login` сохранит токен в `~/.fxtunnel/client.yaml`. Можно и не сохранять его, а передавать переменной окружения:

```bash
export FXTUNNEL_TOKEN="sk_fxtunnel_ваш_токен"
fxtunnel http 3000
```

Подробнее — [«Аутентификация»](/docs/auth).

## Почему не открывается инспектор?

- Инспектор есть не на всех тарифах — смотрите [«Тарифы»](/pricing).
- Если порт 4040 занят, инспектор занимает первый свободный из 4041–4049. Точный адрес — в строке `Inspector:` при запуске.
- Инспектор не запускается с флагом `--no-inspect` и при `inspect.enabled: false` в конфигурационном файле.

## Почему посетители видят страницу с предупреждением?

Так fxTunnel защищает от фишинга: при первом заходе из браузера на поддомен `fxtun.ru` показывается предупреждение. После кнопки «Продолжить» оно не появляется 12 часов. Скриптам достаточно заголовка `X-FxTunnel-Skip-Warning`, а на [своём домене](/docs/custom-domains) страницы нет. Подробнее — [«HTTP-туннели»](/docs/http).

## Что значит «tunnel limit reached»?

Открыто столько туннелей, сколько позволяет тариф. Закройте ненужный туннель или смените тариф. Все ограничения — в разделе [«Лимиты»](/docs/limits).
